# VC-TestOS 后端模块划分

后续按本文顺序，一次只做一个模块。做完并在本机跑通后，再开始下一个。

接口形状以 `front_design/docs/backend-api.md` 为准。前端页面在 `front_design`，当前仍使用本地模拟数据；每个模块完成后再把对应页面接到真实接口。

不按单个接口拆。一个前端页面里的接口共用同一批表、同步任务和推送，拆开会反复改同一层代码。AI Agent 对话本期不做。

## 协作方式

每一轮只做下表中的一个模块，顺序不要跳。开始前先确认该模块的「完成标准」。代码仍按这些层放置：

- `api/`：路由。业务模块放在 `api/overview`、`api/test_plan` 等目录
- `service/`：业务逻辑
- `repo/`：数据库访问
- `models/orm`：SQLAlchemy 表
- `models/dto`：请求和响应
- `models/entity`：领域对象
- `tasks/`：定时任务与触发任务

公共约定从模块 0 起一直有效：

- 前缀 `/api/v1`，时间为 Unix 毫秒
- 错误体 `{ "error": { "code", "message", "detail" } }`
- 除登录外，请求带 `Authorization: Bearer <token>`
- 写操作带 `Idempotency-Key`，响应带 `audit_id`，并写审计日志
- 状态变化用 WebSocket 推送，前端不轮询
- 集群地址和令牌只留在后端
- PostgreSQL 存业务数据，Redis 只存登录会话

## 顺序

| 顺序 | 模块 | 对应前端 | 依赖 |
|---|---|---|---|
| 0 | 底座 | 无独立页面 | 无 |
| 1 | 运行总览 | 运行总览 | 0 |
| 2 | 测试方案 | 测试方案 | 0 |
| 3 | 测试执行 | 测试执行 | 1、2 |
| 4 | 批次报告 | 批次报告 | 3 |
| 5 | 设备配置 | 设备配置 | 1、2 |
| 6 | 系统设置 | 系统设置 | 0、1 |
| 7 | 顶栏与搜索 | 顶栏、命令面板 | 1、2、3 |
| 8 | AI 与 Token | Token 统计，以及各页里的 AI 按钮 | 1–6 |

模块 2 可以和模块 1 并行设计，但测试执行必须等两者都完成。模块 4、5、6 都依赖前面的业务数据，按表中顺序做。

## 模块 0：底座

目标：进程能启动，能登录，错误格式和任务框架就位。还没有业务页面。

接口：

- `POST /api/v1/auth/login`
- `POST /api/v1/auth/logout`
- `GET /api/v1/me`
- `GET /api/v1/health`

数据：用户表、审计日志、幂等键、任务运行记录。登录签发 HS256 JWT（`sub`、`username`、`name`、`role`、`jti`、`iat`、`exp`）。Redis 只记当前有效会话：`auth:user:{user_id}` 对应当前 `jti`，`auth:session:{jti}` 对应 `user_id`。注销或再次登录后，旧 token 立即失效。

任务：调度器能挂定时任务；触发任务有统一入口。本模块先放一个空的清理任务，证明两条链路都能跑。

完成标准：用 `limingyuan` 登录能拿到 token，注销后该 token 失效；故意传错参数时返回文档里的错误体。

不做：机台、方案、告警等业务接口。

---

## 模块 1：运行总览

目标：左侧「运行总览」可以改读后端。包含机台墙、KPI、产出与良率、告警、异常趋势、Rc 偏差、顶部流程条、机台抽屉里的槽位曲线。

接口：

- `GET /machines`
- `GET /machines/{id}`
- `GET /machines/{id}/slots/{index}/curve`
- `GET /stats/kpi`
- `GET /stats/agg5m`
- `GET /stats/anomaly-trend`
- `GET /stats/rc-bias`
- `GET /stats/pipeline`
- `GET /alarms`
- `POST /alarms/{id}/ack`
- `POST /alarms/{id}/unack`
- `POST /alarms/ack-all`
- `GET /alarms/{id}/attribution`
- WebSocket `/ws`，主题 `fleet`、`slots`、`alarms`、`agg_5m`

数据：机台、槽位、过程曲线、测试记录（供 KPI 和 5 分钟汇总）、告警、归因结果、`agg_5m`。流程条若要显示「剩余片数 / 可出报告」，批次表可以先留最小字段，完整批次能力放到模块 3。

定时任务：按设置里的频率同步机群、槽位、测试记录，并重算 5 分钟汇总、扫描告警。集群连不上时退避，不清空已有数据。

触发任务：新告警产生后写入一条归因。本模块用规则生成文档要求的字段即可，大模型归因留到模块 8。`POST /alarms/{id}/attribution` 也留到模块 8。

完成标准：登录后，上述查询能返回与文档一致的 JSON；确认告警后 WebSocket 能收到 `alarms` 消息；总览页上的六块数据都能对上接口，而不是浏览器里的 `live.ts` 模拟。

不做：上电、关机、补偿、方案编辑、连续生产。

---

## 模块 2：测试方案

目标：「测试方案」页可以列出方案、改草稿、校验、发布新版本。

接口：

- `GET /plans`
- `GET /plans/{plan_id}`
- `POST /plans/validate`
- `POST /plans`
- `POST /plan-drafts`
- `PUT /plan-drafts/{id}`
- `DELETE /plan-drafts/{id}`

数据：方案与版本、草稿。发布时转调集群 `POST /api/plans`，同名生成新版本。

完成标准：草稿只存在本地库；发布前校验能返回 `ok / warn / danger`；发布成功后 `GET /plans` 能看到新版本。

不做：`POST /plan-drafts/from-text`（自然语言起草，模块 8）。下发到机台属于模块 3。

---

## 模块 3：测试执行

目标：「测试执行」页的新建任务、执行中、历史批次、测试记录。

接口：

- `GET /models`
- `GET /batches`
- `GET /batch-stats`
- `GET /batch-stats/{batch_id}`
- `GET /production`
- `POST /production/precheck`
- `POST /production/start`
- `POST /production/stop`
- `GET /runs`
- `GET /runs/{run_id}`
- `GET /runs/{run_id}/samples`
- `GET /export/production.csv`
- WebSocket 增加主题 `runs`、`batches`、`production`

数据：型号、批次、批次统计、连续生产状态、测试记录详情。开始生产时写入方案下发记录，供模块 5 的方案历史使用。

定时任务：同步批次、型号，以及测试记录的增量。

完成标准：下发前校验能挡住功率不一致、无剩余片、断开或故障机台；开始和停止会转调集群并记审计；执行中的进度能从接口读到，而不是只改前端内存。

不做：报告图表。`GET /runs/{run_id}/ground-truth` 仅仿真且打开开关时才有，放到模块 6。

---

## 模块 4：批次报告

目标：从测试执行进入 `/report`，先看到统计图和表。AI 总结和补充图后置。

接口：

- `GET /reports/data`

数据：由模块 3 的测试记录聚合。进行中的批次可以出报告；`tested = 0` 的批次不参与计算。

完成标准：单批次和 `?batch_ids=` 多批次的良率、Rc 直方图、不合格帕累托、分机台良率、温差剖面与文档示例字段一致。

不做：`POST /reports/summary`、`/reports/figures`、`POST /reports/export`。这些属于模块 8。

---

## 模块 5：设备配置

目标：「设备配置」页的配置与槽位、一致性与补偿、该机台告警、方案记录。

接口：

- `POST /machines/{id}/power-on`
- `POST /machines/{id}/power-off`
- `POST /machines/{id}/maintenance`
- `POST /machines/{id}/reset`
- `GET /machines/{id}/plan-history`
- `GET /machines/{id}/channel-bias`
- `GET /machines/{id}/compensation`
- `PUT /machines/{id}/compensation`
- `GET /machines/{id}/compensation/history`
- `GET /alarms?machine_id=`（模块 1 已有，这里只确认筛选）

写操作：机台 `DISCONNECTED` 时直接 503，不转发给集群。关机或进入维修时，正在采样的测试记为 `ABORTED`。

完成标准：上电、关机、维修、复位有审计记录，并通过 WebSocket 更新机台状态；补偿写入转调集群，历史能查到操作者和变更内容。

不做：`GET /machines/{id}/compensation/suggestion`（模块 8）。`GET /machines/{id}/drifts` 仅仿真可用，放到模块 6。

---

## 模块 6：系统设置

目标：「系统设置」页能改数据源、同步频率、存储、AI 接入和告警规则，并在仿真模式下注入场景。

接口：

- `GET /settings`
- `PUT /settings`
- `POST /settings/test-connection`
- `GET /sync/jobs/status`
- `PUT /sim/clock`
- `GET /sim/scenarios`
- `POST /sim/scenarios/{name}/apply`
- `GET /sim/fault-catalog`
- `POST /sim/faults`
- `GET /runs/{run_id}/ground-truth`
- `GET /machines/{id}/drifts`

数据：平台设置。`cluster.token`、`ai.api_key`、数据库密码在 GET 时脱敏；PUT 时值不变表示不修改。同步任务 key 固定为 `fleet`、`slots`、`machine`、`runs`、`samples`、`plans`、`batches`、`calib`、`agg`。

完成标准：保存后下一个同步周期使用新频率；低于间隔下限返回 422；`source` 不是 `sim` 时，仿真接口返回 409。

不做：AI 调用本身。

---

## 模块 7：顶栏与搜索

目标：顶栏的当前用户、未确认告警、数据源地址，以及 Ctrl+K 搜索。

接口：

- `GET /me`（模块 0 已有）
- `GET /alarms?acked=false`（模块 1 已有）
- `GET /settings` 中的数据源字段（模块 6 已有）
- `GET /search`

完成标准：搜索能返回机台、批次、方案、测试记录，每项含 `id` 和展示文字。

---

## 模块 8：AI 与 Token

目标：「Token 统计」页，以及前面页面上留空的 AI 能力。AI 不直接写设备。

接口：

- `GET /ai/modules`
- `GET /ai/usage/summary`
- `GET /ai/usage/daily`
- `GET /ai/calls`
- `POST /plan-drafts/from-text`
- `POST /alarms/{id}/attribution`
- `GET /machines/{id}/compensation/suggestion`
- `POST /reports/summary`
- `POST /reports/figures`
- `GET /reports/figures/{figure_id}`
- `GET /reports/figures`
- `DELETE /reports/figures/{figure_id}`
- `GET /reports/figures/{figure_id}.png`
- `GET /reports/figures/{figure_id}/events`
- `POST /reports/export`

数据：`ai_calls`。费用按设置里的模型单价计算。月用量到告警线时生成告警；到 100% 后自动触发的模块暂停，用户手动触发的仍可用。

触发任务：新告警的自动归因从模块 1 的规则实现换成模型；补偿建议按设置的触发方式执行。报告补充图在沙箱执行，只读数据库，60 秒超时。

完成标准：每次 AI 调用有一条 `ai_calls`；Token 页的汇总、按日、按模块和调用明细能对上；方案起草、告警归因、补偿建议、报告总结只产生文字或草稿，不直接改机台。

不做：AI Agent 对话，包括会话、流式消息、对话里的工具调用和待确认设备操作。`agent.analysis` 与 `agent.ops` 只保留模块 id，供以后统计。
